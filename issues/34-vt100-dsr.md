# VT100.DSR sends 6 whatever its argument

*This report was prepared with the help of AI (Claude, by Anthropic). The reproducers were run and the output shown is copied from those runs.*

`VT100.DSR(5)`, the device status report, sends `ESC[6n` (the cursor
position report).

## Reproducer

`VT100Dsr.Mod`:

```oberon
MODULE VT100Dsr; (* DSR(n) sends 6 whatever n is *)
IMPORT VT100, Out;
BEGIN
  VT100.DSR(5); Out.String(" (expected ESC[5n)"); Out.Ln
END VT100Dsr.
```

With voc at `master`:

```
$ voc -O2 VT100Dsr.Mod -m
VT100Dsr.Mod  Compiling VT100Dsr.  Main program.  447 chars.
$ ./VT100Dsr
[6n (expected ESC[5n)
(exit status 0)
```

## Cause and fix

DSR(n) sent ESC[6n whatever n was, so DSR(5), the device status
report, asked for the cursor position instead. It now sends ESC[<n>n.

With the fix:

```
$ ./VT100Dsr
[5n (expected ESC[5n)
(exit status 0)
```

The fix is `patches/0034-VT100.DSR-sends-its-argument.patch`, a `git format-patch` of one commit.

## Environment

voc v2.1.0 at `master`, commit 9701249a (2026-09-25), built with `make all` on Fedora Linux 44, x86_64, gcc 16.2.1.
